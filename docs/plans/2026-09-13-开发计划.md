# 租房留证册 · 开发计划（Implementation Plan）

> **使用说明**：本计划按里程碑组织。每个里程碑开工前，建议按任务再展开为代码级执行计划（TDD 粒度：失败测试→实现→通过→提交）。任务用复选框跟踪。

**Goal:** 交付一款 HarmonyOS（API 21）原生 App：按引导完成房屋检查留证，冻结记录并生成可分享的 PDF 报告与原图归档包，支持入住/退租前后对比。

**Architecture:** 单 entry HAP，四层目录（features/domain/data/infra）；加密 RDB + 沙箱文件；PDF Kit 主渲染 + 截图降级；cameraPicker/图库/文档选择器全免高危权限路径。

**Tech Stack:** ArkTS 严格模式、状态管理 V2、Navigation；`@kit.PDFKit / CoreVisionKit / CoreSpeechKit / CameraKit / MediaLibraryKit / ShareKit / FormKit / ArkData / CoreFileKit(hash) / LocationKit`、`@ohos.zlib`；零三方运行时依赖。

**Spec:** [01-产品设计文档](../design/01-产品设计文档.md) · [02-技术设计文档](../design/02-技术设计文档.md) · [03-功能链路设计](../flows/03-功能链路设计.md)

## Global Constraints（每个任务隐含遵守）

- SDK：`6.0.1(21)`，ArkTS 严格模式，禁止 any/动态属性；
- 措辞红线：只用"记录完整度"，禁用"证据有效性评分"；"校验值仅用于检测文件是否变化，不代表司法鉴定或官方存证"出现在首启弹窗、关于页、PDF 校验页、manifest 四处；
- 导入照片必须标"从相册导入"；OCR/语音结果必须用户确认后才写入最终数据；
- 冻结记录不可变写，修改一律走修订版本；
- 权限白名单：`MICROPHONE`、`LOCATION*`（默认关）、`INTERNET`；**不得**申请 `CAMERA` 与媒体库读写；
- v1 零三方运行时依赖；文案简体中文优先；深浅色适配；
- 每个任务提交前：`hvigorw assembleHap` 通过 + 新增领域逻辑有 hypium 单测。

## 里程碑依赖与接口

```mermaid
flowchart LR
    M0 --> M1 --> M2 --> M3 --> M4 --> M5 --> M6 --> M7
    M2 -. PhotoPipeline .-> M4
    M3 -. meter_reading.confirmed .-> M4
    M4 -. manifest/冻结态 .-> M5
    M5 -. report .-> M6
```

- M2 的 `PhotoPipeline.capture/import(uri): Promise<photoId>`、M3 的 `MeterRepo.confirm(...)`、M4 的 `freeze(id): FreezeResult`、M5 的 `render(inspectionId): Promise<string pdfPath>` 是跨里程碑接口，先行定型并保持签名不变；
- 2 人并行建议切分：A 线（UI/页面：M1→M2.4→M3.3→M4.3→M5.6/5.8→M6），B 线（领域/infra：M0.2/0.3→M2.1/2.7→M3.1→M4.1/4.4→M5.2~5.5/5.7→M6.4）。

## 验收总门禁（Definition of Done）

1. 12 条功能链路（03 文档）全部按验收点通过；
2. 12 条用户故事（01 文档 §2）走查通过；
3. 单测：domain 层行覆盖 ≥70%，关键规则（R1~R7、断行、中性化、状态机、manifest）100% 用例化；
4. 真机矩阵（2 手机+1 平板）冒烟清单全绿；
5. 红线终审：免责文案四处、措辞红线、导入标记、确认门闩、冻结不可变——五项零违规。
